1. Executive Summary & Problem Formulation

1.1 The Municipal Infrastructure Challenge

Rapid urbanization and expanding city boundaries place severe burdens on municipal governance bodies. Essential civic amenities—such as arterial roadways, pedestrian sidewalks, storm runoff canals, water distribution conduits, and electrical illumination grids—require continuous surveillance, rapid defect remediation, and transparent accountability.

Traditional civic grievance setups suffer from fundamental structural limitations:

  • Information Asymmetry: Citizens lodge grievances into opaque portals without verifiable tracking numbers or estimated completion dates.
  • Absence of Field Accountability: Municipal departments lack real-time visibility into whether repairs were performed to code or if materials were actually used.
  • Lack of SLA Enforcement: Critical hazards (e.g., live electrical cable exposure, open manholes) sit unattended without automated escalation or deadline computations.
  • Fragmented Relational Data: Legacy systems struggle to provide consolidated telemetry across disparate municipal wards, departments, and field personnel.

1.2 The CivicFix Solution

CivicFix is designed to solve these systemic failures. Combining modern document database modeling (MongoDB) with a high-performance, responsive single-page web interface (React 18 & Vite), the system establishes an end-to-end audit trail for every civic failure reported.

Core Functional Objectives

Stakeholder Primary Capabilities & Value Delivered
Citizens Lodge photo-verified complaints with GPS geolocation, track live timeline progression, receive resolution notices, and submit 1–5 star ratings.
Municipal Admins Executive command dashboard with Recharts telemetry, SLA violation alerts, complaint triage registry, and workforce management.
Field Specialists Digital work order queue, state transitions (Pending → In Progress → Work Completed), and before-and-after photographic evidence uploads.

CivicFix is architected following clean separation of concerns across four logical tiers:

Responsive Single Page Application (SPA) utilizing React Router v6 for role-guarded routes, React Context API for global authentication and toast alerts, and Recharts for live municipal KPI visualization.
Tier 2: API Gateway & Security Guard Express.js • JWT • Multer • CORS • Morgan
Stateless RESTful gateway enforcing JWT token authentication, role authorization middleware (RBAC), multi-part image streaming for photographic evidence, and comprehensive request logging.
Tier 3: Business Logic & Orchestration Service Node.js Controllers • SLA Engine • Audit Dispatcher
Autonomous controller layer managing SLA deadline calculation, complaint tracking code generation (CF-YYYY-XXXX), notification broadcasting, and status transition enforcement.
Tier 4: Document Data Layer MongoDB 8/9 • Mongoose • Compound Indexes • $facet
Operational document datastore with schema validation, compound and sparse indexing, multi-stage aggregation pipelines for telemetry, and atomic transaction updates.

4. End-to-End Complaint Lifecycle & SLA Automation

The core lifecycle guarantees transparency, immutability, and accountability:

1
Citizen Submission & SLA Calculation

The citizen uploads a photo, selects a category and ward, and describes the defect. The backend computes the deadline: resolutionDeadline = submissionDate + category.defaultSlaHours, generates an audit tracking code (e.g., CF-2026-104921), and saves initial status Pending.

2
Administrative Triage & Worker Dispatch

Municipal admins inspect incoming complaints on the triage board. The admin selects a qualified field technician from the relevant department. Status transitions to Assigned, creating an Assignment record and alerting the worker.

3
Field Arrival & Work Inception

The technician reviews the GPS coordinates, arrives on site, and clicks "Start Work". Status transitions to In Progress with an immutable entry in StatusHistory.

4
Field Repair Execution & Evidence Upload

Technician completes physical repairs (e.g., asphalt patching, pipe sleeve replacement). The technician uploads photographic proof (before & after), logs materials used and cost incurred, transitioning the state to Work Completed.

5
Administrative Audit & Citizen Feedback

Admin verifies photographic evidence and marks the complaint Resolved. The citizen receives an instant alert and submits a 1–5 star rating with satisfaction remarks, updating the worker's average rating.

6. MongoDB Advanced Aggregation Pipelines

CivicFix leverages native MongoDB pipelines instead of expensive client-side joins or traditional relational SQL queries:

6.1 Multi-Faceted Executive Telemetry Pipeline (`$facet`)

Computes three disparate KPI dimensions (status breakdown, priority distribution, and overdue ticket counts) in a single database round-trip for the admin dashboard: 

const [summary] = await Complaint.aggregate([
  {
    $facet: {
      statusBreakdown: [
        { $group: { _id: '$status', count: { $sum: 1 } } }
      ],
      priorityBreakdown: [
        { $group: { _id: '$priority', count: { $sum: 1 } } }
      ],
      overdueTickets: [
        {
          $match: {
            status: { $nin: ['Resolved', 'Rejected'] },
            resolutionDeadline: { $lt: new Date() }
          }
        },
        { $count: 'overdueCount' }
      ]
    }
  }
]);

6.2 Cross-Collection Department Resolution Pipeline (`$lookup` & `$filter`)

Calculates real-time municipal departmental performance by joining categories and complaints: 

db.departments.aggregate([
  {
    $lookup: {
      from: 'categories',
      localField: '_id',
      foreignField: 'departmentId',
      as: 'deptCategories'
    }
  },
  {
    $lookup: {
      from: 'complaints',
      localField: 'deptCategories._id',
      foreignField: 'categoryId',
      as: 'complaints'
    }
  },
  {
    $project: {
      name: 1,
      code: 1,
      totalComplaints: { $size: '$complaints' },
      resolvedCount: {
        $size: {
          $filter: {
            input: '$complaints',
            as: 'c',
            cond: { $eq: ['$$c.status', 'Resolved'] }
          }
        }
      },
      inProgressCount: {
        $size: {
          $filter: {
            input: '$complaints',
            as: 'c',
            cond: { $in: ['$$c.status', ['Assigned', 'In Progress', 'Work Completed']] }
          }
        }
      }
    }
  }
]);

6.3 Pre-Defined Database Aggregation Views

Three views defined in database/mongo-aggregation-views.js materialize key operational abstractions:

  • complaint_overview: Denormalizes complaints with citizen names, ward designations, and department codes.
  • department_complaint_summary: Aggregates caseload density, resolution rates, and budget allocations per department.
  • worker_performance_summary: Computes active work order counts, completed repairs, and citizen rating averages per field specialist.
